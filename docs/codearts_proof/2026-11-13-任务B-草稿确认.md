## 1. 需求分析

原始 Prompt：

```text
用户选择要整理的内容及日期，默认不读取其他日记；只有用户主动勾选“参考我最近的日记”才传 includeRecentDiaries:true。通过 api('/companion/prepare',{method:'POST',body:{message,date,includeRecentDiaries}}) 获取草稿。展示可编辑正文、日期、私密标识、来源和简洁执行步骤。预览页面必须明确“尚未保存为日记，草稿已暂存服务端”，不能在预览时调用普通日记保存接口。用户点击确认后 POST /companion/drafts/:id/confirm，body 为 {text}；展示真实 diaryId 和返回 url 链接。取消使用 DELETE /companion/drafts/:id。若返回 care 且 draft 为 null，只展示支持提示，不继续生成或保存。
```

码道分析或方案摘要：

- 材料只来自用户勾选的当前页面消息，按勾选顺序拼接，1–2000 UTF-16；为空或超限不发请求。
- 日期使用本地 `getFullYear/getMonth/getDate` 拼 `YYYY-MM-DD`，不使用 UTC 截断。
- `includeRecentDiaries` 每次按当前勾选状态发送严格布尔值。
- 预览只展示；正文编辑保存在页面内，不调用日记保存接口；确认时才 POST confirm。
- `draft:null` + care 停止，不给确认按钮；`40900/41000/40400/40100/-1` 分别映射。
- 超时用同一 `draftId` GET 查证；取消只是状态变更，不删除日记。

人工选择、纠正及原因：未把 `code===409` 当作冲突（后端 JSON code 为 `40900`）；未自行拼 diaryId；站内链接仅接受 `diary-write.html?date=YYYY-MM-DD`。
