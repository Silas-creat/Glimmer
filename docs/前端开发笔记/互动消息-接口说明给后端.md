## 一、需要实现的两个接口

### 1. 拉取互动消息

```
GET /api/interact/notifications?limit=20
Authorization: Bearer <token>
```

**返回结构**

```json
{
  "code": 0,
  "msg": "ok",
  "data": {
    "unread": 3,
    "list": [
      {
        "id": 1024,
        "type": "like",
        "from": { "id": 4, "nickname": "小光", "avatar": "" },
        "diaryId": 9,
        "diaryTitle": "今天出门，看见楼下的猫在晒太阳",
        "content": "",
        "createdAt": "2026-11-03 21:12:00",
        "read": false
      },
      {
        "id": 1023,
        "type": "comment",
        "from": { "id": 4, "nickname": "小光", "avatar": "" },
        "diaryId": 9,
        "diaryTitle": "今天出门，看见楼下的猫在晒太阳",
        "content": "我家楼下也有一只",
        "createdAt": "2026-11-03 21:05:00",
        "read": false
      }
    ]
  }
}
```

**字段说明**

| 字段 | 类型 | 说明 |
|---|---|---|
| `type` | string | `like`（赞）/ `favorite`（收藏）/ `comment`（评论），前端按这三种渲染文案 |
| `from` | object | 触发这条互动的人：`id`、`nickname`、`avatar`（空字符串表示没上传，前端用昵称首个字代替） |
| `diaryId` | number | 被互动的日记 id，前端点击后跳 `diary-public.html?id=xxx` |
| `diaryTitle` | string | 可选，日记内容前 20 字左右，用于展示 |
| `content` | string | 仅评论有值，评论内容（前端会拼接成「小光 评论了你：xxx」） |
| `createdAt` | string | `YYYY-MM-DD HH:mm:ss` |
| `read` | boolean | 是否已读 |
| `unread` | number | 未读总数，用于右上角红点（>99 前端显示 99+） |

**空数据也要返回合法结构**（前端会显示「还没有新的互动」）：

```json
{ "code": 0, "msg": "ok", "data": { "unread": 0, "list": [] } }
```

### 2. 标记已读（可选，但建议做）

```
POST /api/interact/notifications/read
Body: { "ids": [1024, 1023] }      // 传 ids 标记指定几条
   或 { "all": true }              // 全部标记已读
```

返回：`{ "code": 0, "msg": "ok", "data": { "unread": 0 } }`

## 二、什么时候生成一条通知

| 触发动作 | 生成的通知 |
|---|---|
| 用户 A 点赞 用户 B 的日记 | B 收到一条 `type=like`，`from=A`，`diaryId=该日记` |
| 用户 A 收藏 用户 B 的日记 | B 收到一条 `type=favorite` |
| 用户 A 评论 用户 B 的日记 | B 收到一条 `type=comment`，`content=评论内容` |
| 用户给自己点赞/评论 | **不生成**（自己不该收到自己的通知） |

---

## 三、去重与合并规则（建议）

1. **同一个人对同一篇日记的同类操作只保留一条**：A 取消点赞再点一次，不新增通知，只刷新时间；
2. **评论不去重**：每条评论都是一条独立通知（前端按条展示）；
3. 列表按 `createdAt` 倒序，最多返回 `limit` 条（默认 20，前端目前按 20 条拉）。

## 四、数据表建议

```sql
CREATE TABLE notifications (
  id          BIGINT PRIMARY KEY AUTO_INCREMENT,
  to_user_id  BIGINT NOT NULL,
  from_user_id BIGINT NOT NULL,
  type        ENUM('like','favorite','comment') NOT NULL,
  diary_id    BIGINT NOT NULL,
  content     VARCHAR(255) DEFAULT '',
  is_read     TINYINT(1) NOT NULL DEFAULT 0,
  created_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  UNIQUE KEY uk_dedupe (to_user_id, from_user_id, type, diary_id),  -- 赞/收藏去重
  KEY idx_to_user (to_user_id, created_at)
);
```

> 评论因为要保留多条，可以在唯一键里带上 `content` 或直接用 `comment_id`，
> 具体怎么设计由你决定，只要接口返回结构不变即可。

## 五、前端现在怎么处理

- 页面加载时调一次 `GET /api/interact/notifications?limit=20`；
- **接口不存在时（404）** → 显示「还没有新的互动」，不会报错、不会白屏；
- 有数据 → 渲染成列表：`头像 + 「小光 赞了你的日记」 + 日记标题 + 时间`，点击跳详情；
- `unread > 0` → 标题右侧显示红点和数字。

也就是说：**后端把这个接口补上，前端一行都不用改，刷新就有数据。**
