## 一、现在真的做完了什么

### 1. 后端：18 个接口、10 张表，全部实测通过

| 模块 | 接口数 | 内容 |
|---|---|---|
| 账号 | 4 | 注册、登录、当前用户、修改资料（JWT 鉴权） |
| 日记 | 7 | 新增、修改、删除、我的列表、公开流、按天查询、单篇（私密返回 404） |
| 漂流瓶 | 4 | 扔、捞、我的瓶子、给瓶子主人送祝福 |
| 祝福 | 3 | 收到、送出、标记已读 |

数据库 10 张表：`users / diaries / bottles / bottle_picks / blessings / rooms / room_members / messages / reports / mutes`

统一的返回结构 `{code, msg, data}`，统一的 401 处理，所有 SQL 用参数占位（防注入）。

### 2. 前端：16 个页面（15 功能 + 1 占位）

已接真实接口的 **4 个页面**：

- `login.html`：注册 / 登录，token 存本地，失败有中文提示
- `diary-write.html`：写日记（一人一天一篇）、背景图、公开/私密切换、进入自动回填
- `diary-mine.html`：日历视图，数据来自 `/diary/mine`
- `discover.html`：发现页，数据来自 `/diary/public`，桌面 3 列 / 手机 2 列

另外全局做了：

- `api.js` 统一请求封装（带 token、401 跳登录、地址自动回退）
- `ui.css`：修横向溢出、底部导航五等分、头像改首字母圆点（断网不裂图）
- 响应式：桌面端内容居中限宽 960（沉浸页 720），手机端保持 430 竖屏
- 品牌统一为“微光同行”

### 3. 演示链路已经能跑通

> 手机 A 登录写一篇公开日记 → 手机 B 登录后在发现页刷到 → 点开作者的私密日记显示“内容不存在”

数据库里预置了 6 篇公开日记（小海、小光），打开发现页就能看到真实数据。
