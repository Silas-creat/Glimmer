# 从零安装与部署复现

> 适用版本：包含本指南和部署工程修复的版本。业务基线为 `2112271`，但该旧提交不包含启动器、检查器与 `.gitattributes` 修复，不能单独导出它复现本指南全部结果。
> CodeArts 原始结果见 [部署复现与交付收尾](../codearts_proof/2026-11-15-部署复现与交付收尾.md)；后续独立工程复验见 [部署工程修复与复验](../reports/2026-11-15_部署工程修复与复验.md)。历史日志保持原样。
> 不覆盖现有数据库、不读取/打印真实凭证、不配置真实模型。

## 1. 环境要求（实测值）

| 项 | 要求 | 本次实测 |
|---|---|---|
| Node.js | ≥ 18（`package.json` engines） | 24.22.0 |
| npm | 随 Node 提供 | 11.19.1 |
| MySQL | 8.0+；推荐使用已有的 `mysqld.exe` | 8.4.13（`D:/mysql/bin/mysqld.exe`） |
| 操作系统 | Windows（一键脚本）/ Linux（`deploy.sh`） | Windows 11 |
| 端口 | 前端、后端、测试数据库各一个空闲端口 | 8090 / 3001 / 3311 |

> 现有开发环境可能已占用 8081 / 3000 / 3307。复现验收不要复用这些实例，也不要停止它们。

## 2. 获取干净源码

```bash
git archive --format=zip HEAD -o <隔离目录>/source.zip
# 解压到新建的 checkout 目录；Windows 可使用 Expand-Archive，避免本机 tar 的中文文件名兼容问题。
```

或使用已发布的源码包。不要复制以下内容：

- `后端源码/.env`（含数据库密码）
- `后端源码/node_modules`
- `node_modules`
- MySQL 数据目录（`mysql-data*`、`data*`）
- 运行日志、临时页面、浏览器配置

校验（应与固定版本一致）：

```bash
sha256sum <隔离目录>/checkout/前端参考/chat-companion.js
# 31c567e972b963bbce63877728958dbd755890a1afba7456f924e781b3a22270
```

> 当前 `.gitattributes` 显式固定 `*.sh text eol=lf`。本机 `core.autocrlf=true` 下，旧提交导出确实出现 CRLF；带新属性规则的导出已核对四个 shell 文件均为 LF。未提交的修复不会自动进入 `git archive HEAD`，验证工作区属性时可用 `--worktree-attributes`。

## 3. 安装依赖

```bash
cd <隔离目录>/checkout/后端源码
npm ci --no-audit --no-fund
```

预期：`added 143 packages`，退出码 0。若需要离线安装，可先在有网络的环境准备 `node_modules` 压缩包，但不得用“复制现有依赖”冒充干净安装通过。

## 4. 生成隔离 `.env`

只复制键名，不复制现有值：

```bash
cp .env.example .env
```

最少需要以下键（`DEEPSEEK_API_KEY` 留空即为本地规则模式）：

```text
HOST=127.0.0.1
PORT=3001
NODE_ENV=development
DB_HOST=127.0.0.1
DB_PORT=3311
DB_USER=root
DB_PASSWORD=<独立实例的随机密码>
DB_NAME=peizhe_deploy_20261115
JWT_SECRET=<随机字符串>
JWT_EXPIRES_IN=7d
DEEPSEEK_API_KEY=
DEEPSEEK_API_URL=https://api.deepseek.com/chat/completions
DEEPSEEK_MODEL=deepseek-chat
DEV_SMS_CODE=123456
SMS_ENABLED=false
```

安全要求：

- `.env` 不提交、不截图、不打印值。
- 不要连接现有 3307 实例；不要把现有 `.env` 复制进隔离目录。

## 5. 启动独立测试数据库（以 3311 为例）

初始化（数据目录必须为新建空目录，且不得指向现有库）：

```bash
<MySQL>/bin/mysqld.exe --no-defaults --initialize-insecure \
  --basedir=<MySQL> --datadir=<独立数据目录>/mysql-data-3311
```

启动：

```bash
<MySQL>/bin/mysqld.exe --no-defaults --basedir=<MySQL> \
  --datadir=<独立数据目录>/mysql-data-3311 \
  --port=3311 --bind-address=127.0.0.1 --mysqlx=OFF --console
```

注意：

- `--no-defaults` 必须放在第一个参数，避免读取机器上的 `my.ini`。
- 本指南以下步骤演示手动准备隔离库；也可使用已修复的 [安装器](../../setup/README.md)。新安装器拒绝已有数据目录和占用的显式端口；已有 `.env` 的建表/迁移必须显式 `--use-existing`，不会重置认证。历史 CodeArts 复现使用旧安装器，因此当时没有走该入口。
- 为独立实例设置随机 root 密码时，必须显式指定 `-P 3311`，核对 `@@server_uuid` 与本轮数据目录 `auto.cnf`、以及 `@@port` 后再执行。下面是 SQL 模板；实际密码通过受保护的交互会话或内存连接传入，避免出现在命令行历史中：

```sql
ALTER USER 'root'@'localhost' IDENTIFIED BY '<独立实例随机密码>';
```

## 6. 初始化数据并启动后端

```bash
cd <隔离目录>/checkout/后端源码
node scripts/init-db.js
node scripts/init-db.js    # 第二次验证幂等
```

预期：

- `init-db.js` 两次均退出 0；第二次不重复灌入脏数据。
- 后端由下一步启动器启动，使用 `.env` 中的 `PORT`（本例 3001）。不要先手动启动后端，否则启动器会因端口占用拒绝继续。
- 完成下一步后检查后端与前端代理：

```bash
curl -s http://127.0.0.1:3001/api/health
curl -s http://127.0.0.1:8090/api/health
```

预期关键字段：

```json
{"code":0,"data":{"db":{"connected":true},"ai":{"configured":false}}}
```

## 7. 启动前端

```bash
cd <隔离目录>/checkout
node setup/start.js --no-open --port 8090
```

打开 `http://127.0.0.1:8090`。

说明：

- `setup/start.js` 会读取 `.env` 的 `DB_PORT` 与 `PORT`；若 8090 被占用会顺延，以窗口输出为准。
- 系统环境变量优先于 `.env`。后端端口被占用时会在启动 MySQL、执行迁移前拒绝继续；健康接口不能证明另一进程属于当前目录。请停止已确认的旧实例，或选择空闲 `PORT`，不要按端口盲目结束进程。
- MySQL 已启动时使用 `.env` 中明确配置的实例。自动拉起只支持已初始化的本地库，可通过 `MYSQL_BASEDIR` 和 `MYSQL_DATA_DIR` 指定路径；不会初始化或改密码。迁移或数据库健康失败会中止。
- 正常 Ctrl+C 会停止前端与本次创建的后端，MySQL 保持运行。强制结束进程可能绕过退出钩子，重新启动前需核对遗留进程。
- Linux 上若使用 `scripts/*.sh`，先确认换行：

```bash
grep -rlU $'\r' scripts/*.sh || true
```

若存在 CRLF，转换为 LF：

```bash
sed -i 's/\r$//' scripts/*.sh
```

## 9. 实例归属与零写入核对

启动前/后各记录一次：

```bash
netstat -ano | findstr ":8090 :3001 :3311 :8081 :3000 :3307"
sha256sum 后端源码/.env
```

- 3311/8090/3001 必须是本轮新实例；3307/3000/8081 的 PID、启动时间与命令行不得变化。
- CodeArts 原报告的 `D:/mysql/data` 指纹没有证明是现有 3307 的实际数据目录，不能据此断言该实例零写入。正常运行实例的文件统计也不能替代表内容核对。
- 在无凭证条件下无法读取现有库表清单，报告中应标“库表内容零写入未验证”，不得宣称通过。

## 10. 静态检查器

```bash
npm test                                  # 部署前静态自检
node scripts/check-frontend.js            # 前端内联脚本语法
node scripts/check-pages-runtime.js ../前端参考 --base http://127.0.0.1:3001 --phone <合成测试手机号> --code <验证码>
```

- `npm test` 本轮修复前为 7 失败（3 项前端路径 + 4 项 shell CRLF），修复后 131 通过 / 0 失败。
- `check-frontend.js` 实际检查当前顶层函数式 `api.js` 契约及本地外链脚本语法；当前结果 107 通过 / 1 警告 / 0 失败。警告来自未接入 API 的 `diary.html` 的可选保护调用，主 API 契约没有跳过。
- `check-pages-runtime.js` 需要可用的后端；不要指向现有 3000 实例做写入型检查。
- runtime 脚本必须显式指定目标与合成账号，拒绝跨 origin 和重定向；它使用假 DOM，只检查实际执行的初始化路径，不等于浏览器端到端验收。

## 11. 常见故障

| 现象 | 原因 | 处理 |
|---|---|---|
| `npm ci` 报 `EPERM` | 文件或缓存访问被拒；仅凭该错误无法确定是权限、锁还是安全软件 | 根据确切错误路径授权访问并重试；不要关闭 TLS 校验或复制现有依赖冒充干净安装 |
| `mysqld` 启动后端口不监听 | 需查看错误日志，原记录未证明由文件监视引起 | 检查数据目录、参数、字符编码和权限；`--no-defaults` 放首位；本轮仓库内独立目录实测可启动 |
| `init-db.js` 报 `DB_PASSWORD 没填` | 独立实例使用空密码，但配置校验要求非空 | 为独立实例设置随机密码并写入隔离 `.env`；不要改现有实例 |
| 3311 连接被拒 | 实例未启动或已被清理 | 重新启动并在同一验收脚本内完成初始化与回归 |
| `scripts/*.sh` 报 `bad interpreter` | CRLF 换行 | 转为 LF 后重试 |

## 12. 安全与交付边界

- 不提交 `.env`、数据库目录、`node_modules`、运行日志。
- 不打印 `DB_PASSWORD`、`JWT_SECRET`、`Authorization`、JWT 或真实手机号。
- 不配置真实模型；`ai.configured=false` 只能表述为“本地支持回复”。
- 不覆盖既有 `docs/review/**`、`docs/codearts_proof/**` 与失败日志。
- 浏览器端到端、真实模型、手机硬件、多实例并发不在本文自动验证范围。
