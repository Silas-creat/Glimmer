# 微光同行：本机环境与启动说明

配置日期：2026-11-12。

> 说明：本文件记录原开发机的环境与启动细节。仓库中不含 `.runtime/` 下的本机数据与日志；
> 在新机器上请直接使用根目录的 `一键安装.bat` / `一键启动.bat`，或按 [../README.md](../../README.md) 的「快速开始」。

## 原机器与仓库的区别（2026-11-13 补充）

以下环境数字和 `.runtime` 日志属于原开发机。该机器 `D:/微光同行/启动项目.bat` 实际调用上一级 `.runtime/start.cjs`，运行的是 `二十三稿`；它不在 Glimmer 仓库内。Glimmer 自带的一键脚本对应 setup/install.js、setup/start.js，是另一套启动逻辑，不能直接等同于当时验证过的本机启动器。后者可能复用已占用 3000 的后端；修改 Glimmer 后须先核对实际服务目录再验收。详见 [码道开始前必读.md](../project/码道开始前必读.md)。

## 仓库启动入口（需在实际环境验证）

1. 双击仓库根目录的 **一键启动.bat**（第一次使用先跑 **一键安装.bat**）。
2. 浏览器访问 **http://localhost:8080**，以启动窗口实际显示的端口为准。
3. 演示登录：手机号 **13800138000**，验证码 **123456**。页面即使把输入框称为密码，实际也使用开发验证码。

服务在后台运行，关闭启动窗口不影响服务。电脑重启后，重新双击启动文件即可；重复运行启动文件会复用本项目已经启动的服务。

也可以在 PowerShell 中执行：

```powershell
Set-Location -LiteralPath '<项目根目录>'
node setup/start.js
```

## 日志与检查

- `.runtime/logs/mysql.log`：项目独立 MySQL 实例日志。
- `.runtime/logs/backend.log`：后端日志。
- `.runtime/logs/frontend.log`：前端静态服务和代理日志。
- `.runtime/logs/migration.log`：最近一次启动器执行数据库迁移的输出。
- `.runtime/services.json`：后台进程编号和实际访问地址。
- `.runtime/运行验证.jpg`：本次浏览器验证截图。

健康检查：

```powershell
Invoke-RestMethod 'http://127.0.0.1:3000/api/health'
Invoke-RestMethod 'http://localhost:8080/api/health'
```

应看到 `code: 0`，以及 `data.db.connected: true`。
