# 微光同行：陪伴核心接口契约

所有路径以下均包含 `/api`。页面使用已有 `api.js` 时传入 `/ai/...` 或 `/companion/...`，因为包装器已带 `/api`。响应统一 `{code,msg,data}`，成功 `code:0`；错误可能带 `data.care`，前端不能仅显示 msg 而丢弃关怀信息。

版本核对：2026-11-13，Glimmer 二十四稿合并基线。此次合并没有更改 AI/companion 请求协议；主要变化是必须同时保护社交/举报/审核增量。路径与运行目录先见 [码道开始前必读.md](../project/码道开始前必读.md)。

`api()` 返回解析后的 JSON，不包含可依赖的 HTTP Response 对象。业务错误通常为 HTTP 状态码 × 100，例如 40100、40400、40900、41000；网络失败为 -1。默认 401 会清理登录状态并跳登录页；需本页处理未登录状态时，按现有包装器使用 `silent401:true`，仍应显示登录要求并处理失效状态。

## 会话与记忆

`POST /api/ai/chat`

```json
{"message":"今天完成了一件小事，想记下来。","remember":false,"history":[]}
```

- message：非空文字，最多 2000 个 UTF-16 单元（与 JS 字符串 length 一致）。
- remember:false：使用请求中的临时历史，不读写账号聊天记录与长期摘要；刷新页面后本页历史消失。
- remember:true：必须登录；从本人数据库历史与摘要恢复上下文。客户端 history 不用于生成，但若传入仍会先校验格式和长度；保存模式建议不传或传空数组。
- 为兼容旧客户端，已登录且省略 remember 时仍会保存；新页面必须明确发送布尔值。
- history：最多 16 条 `{role:"user"|"assistant",content:"..."}`，单条 1–2000；不能传 system。前端保留完整显示，但发送的历史条目必须满足此长度约束。
- data：`userMessage`、`reply:{content,...}`、`saved`、`provider:{provider,isReal,model,notice}`、`degraded`、`care`、`memoryUpdated`。
- provider.isReal 表示该次回复是否使用真实模型；degraded 表示本地模式/降级。不要把本地回复标成大模型结果。
- 摘要异步更新，memoryUpdated 当前为 false，最新结果需查询 memory。当前保留最近 8 条消息，较旧部分再进入摘要；刚开始聊天时 hasMemory:false 可以同时有 totalMessages>0。无 Key 或摘要更新失败时也可能只有历史而没有摘要，不能把空摘要写成“所有记录已清空”。
- messages 第1页是最近消息，页内按时间正序；后续页是更早消息，分页加载时向前合并并按 ID 去重。
- 临时上下文 helper 当前只有 send()，固定 remember:false；接入模式切换/清除时须真正隔离或重建其历史状态，清空 DOM 不足以清除下一次请求上下文。

| 接口 | 权限 | 用途/主要字段 |
|---|---|---|
| GET /api/ai/status | 可匿名 | 当前配置的 provider 信息；不等于上游连通性测试。 |
| GET /api/ai/messages?page=1&size=30 | 登录 | list、total、hasMore；当前页按时间正序显示。 |
| GET /api/ai/memory | 登录 | summary、hasMemory、totalMessages、pendingMessages、summaryUntilId、lastChat。 |
| DELETE /api/ai/memory | 登录 | 清空本人的聊天记录和摘要，返回 deleted；不删除日记或日记草稿。 |

本次聊天页默认临时模式；完整保存开关、历史、记忆查看与清除界面由码道接入。临时模式不得调用个性化 greeting 接口读取持久摘要。

## 准备私密草稿

`POST /api/companion/prepare`，必须登录：

```json
{"message":"今天散步后心情轻松一些，想保留这个瞬间。","date":"2026-11-14","includeRecentDiaries":false}
```

- date 必须为实际存在的 YYYY-MM-DD；message 1–2000，不静默截断。
- 只有 includeRecentDiaries 严格等于 true，才读取本人目标日期及之前 6 天内最多 3 篇日记。
- data.draft：`id`（UUID）、`date`、`text`、`sources:[{id,date,url}]`、`provider`（字符串）、`status`、`expiresAt`（UTC 时间）。
- data.trace：公开的执行状态摘要，包含 validate、sources、draft 等步骤；不是模型内部推理。
- data.provider 是字符串，和聊天的 provider 对象不同；`local` 表示本地规则保留原话。
- 草稿存于服务端，30 分钟后不可确认；此步骤**不会写入 diaries**。界面应说“尚未保存为日记”，不能说“没有任何内容存储”。
- 检测到明确危机词时 data.draft 为 null，返回 care 与停止步骤；不读日记、不调用模型、不创建草稿。

## 审阅、确认与取消

| 接口 | 请求 | 结果 |
|---|---|---|
| GET /api/companion/drafts/:id | 无 | 返回 data.draft；仅本人读取，不存在或属于他人均 404。 |
| POST /api/companion/drafts/:id/confirm | `{text:"修改后的内容"}` 或 `{}` | 事务写入私密日记；省略 text 使用原草稿。text 1–5000。 |
| DELETE /api/companion/drafts/:id | 无 | 返回 data.draft；取消待确认草稿，重复取消幂等，不会删除已保存日记。 |

确认成功 data：`{draftId,diaryId,date,url,status:"confirmed",isPublic,care}`。首次 isPublic 为 false。返回 url 为现有 `diary-write.html?date=...`；以服务端真实返回值展示结果。

- 同一草稿重复/并发确认返回相同 diaryId，不重复写入。
- 不同草稿同日竞争只会创建一篇；当天已有日记返回 409，不覆盖。
- 草稿已取消为 409，过期为 410；修改日期需重新 prepare。对应 JSON code 为 40900/41000。
- GET 可返回 pending/confirmed/cancelled/expired；过期草稿 GET 仍可返回 200 和 expired 状态，不能只以 HTTP 成功判定可确认。
- 编辑内容仅在 confirm 提交，GET 不会保存编辑；当前没有 PATCH 草稿或草稿列表接口。确认超时可用同一 id 重试；重新 prepare 会产生新草稿。
- 成功确认后，即使草稿过期，再次确认仍返回原记录；若日记后来被本人删除则 410，不重建。
- 已确认草稿不能取消，返回 409。
- 如果本人后来修改了日记可见性，重复确认会如实返回当前 isPublic，不把日记自动改回私密。

## 关怀与错误展示

care 格式为 `{message,lines:[{name,phone,...}]}`。使用 textContent，电话链接只允许电话字符，禁止把模型输出或用户文字作为 HTML。

公开日记、评论、祝福、瓶子等混合违规内容仍会被拦截，但可在错误 data 中携带 care；私信/群消息保持原 blocked 协议。关怀不抵消内容规则。识别基于词库，不覆盖全部危机表达。
