## P2：普通游客上下文被误判为旧账号内容

位置：`前端参考/chat-companion.js:1400–1413` 的 `classifySession/hasLegacyContext`，以及 `1570–1575` 的发送隔离分支。

`hasLegacyContext()` 将 `state.turns.length` 和 `state.panelKind` 等通用页面状态当作旧账号上下文。游客首轮后 `turns.length` 非零，下一次发送被分类为 `signed-out-with-context`，进入 `isolateSignedOutContext`，清空聊天、helper 上下文和输入后直接返回。

真实浏览器复现：

1. 无登录凭证打开 `http://127.0.0.1:8081/chat.html`，保持临时模式。
2. 发送“验收测试：今天我完成了一件小事。”，正常得到回复。
3. 不刷新页面，发送“验收测试：我还想继续说第二件小事。”。
4. 已有聊天和输入消失，页面只剩“登录状态已失效，已转为临时对话；本次不保存”。

独立断言进一步确认：第二次没有发出 `/ai/chat`；首条接口失败后再次发送也没有请求；游客首轮后打开“历史对话”会清空匿名聊天。这后两项是模拟 DOM/接口验证，未冒充浏览器实测。三项属于同一个上下文归属判断错误。

现有 EDGE-R8 测试覆盖“首条发送”“刷新后首条发送”“并发双击”，没有覆盖同一页面顺序发送两轮；失败恢复用例只检查原文恢复，没有再次点击发送。这解释了为何既有全量命令全绿而页面仍有缺陷。

复跑新增正确行为断言（仓库根目录）：

```powershell

```

本脚本退出 0 才表示全部预期行为通过。它与旧 `identity-boundary-repro.cjs` 的含义不同：旧脚本退出 0 代表成功复现旧缺陷，不能作为验收入口。

修复时应明确区分本页匿名上下文与此前账号拥有的上下文，保留真实退出登录/换号隔离，不以删除安全检查换取游客通过。具体任务见 [给CodeArts的游客连续聊天补修指令.md](给CodeArts的游客连续聊天补修指令.md)。

这是当时沙箱访问本机 MySQL 的网络限制，不是这两条命令的 TLS 证书链错误。CodeArts 的“当时完整回归没有通过”记录应保持原样；本报告的后续独立通过结果不能倒填为它当时通过。
