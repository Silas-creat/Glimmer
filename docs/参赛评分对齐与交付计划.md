# 微光同行：按初赛评分标准收敛版本

依据：用户提供的《初赛阶段评分标准》截图，以及西安邮电大学站[作品要求](https://developer.huaweicloud.com/competition/information/1300000372/circumstance)、[赛程](https://developer.huaweicloud.com/competition/information/1300000372/introduction)。初赛截止 2026-11-18，内部冻结目标 11-17，按北京时间安排；提交时间与页面变更以官网为准。

## 主方向

**可控记忆的情绪陪伴：表达 → 授权参考本人记录 → 草稿预览 → 本人确认 → 私密保存 → 下次续聊。**

优先面向有日常压力、希望倾诉并回顾生活记录的大学生。现阶段这是待真实用户验证的定位，不能把假设写成调研结论。产品提供生活记录和情绪支持，不提供诊断或治疗结论。

核心差异不在“也能聊天”，而在用户能选择是否记住、查看记忆、清除记忆，并控制从聊天到私密日记的每一次写入。当前实现是有明确授权和确认步骤的工具工作流，不能宣称已经实现自主规划、多智能体协作或临床效果。

## 码道承担的核心工作

评分表写明“全程以码道为核心工具开发，留存完整使用痕迹”，官方同时要求码道为核心 AI 编程工具。因此仅把配色、文案等小修改留给码道不足以证明该项。当前工作不构成赛事合规保证，最终认定由组委会决定。

建议让码道实际承担以下连续链条，难点已由后端接口隔离，但工作仍直接决定产品是否完整可用：

1. **需求分析**：阅读本文件和接口契约，列出临时模式、保存模式、未登录、正在发送、过期、取消、同日冲突、模型不可用等状态。
2. **核心生成与重构**：完成记忆控制/续聊页面、草稿预览编辑/确认页面。任务原文见 `码道核心功能接入任务.md`。
3. **测试与排错**：编写并运行页面到真实接口的合成账号验收；至少留下一个真实问题的复现、修复和复验过程。没有遇到问题就如实记录，不制造或伪造排错历史。
4. **部署与复现**：改造依赖路径配置，修复现有静态检查器，在干净环境完成安装、迁移、启动和测试。
5. **过程归档**：每次按 `码道交互记录模板.md` 记录原始 Prompt、回复/截图、采纳修改、执行结果和人工判断。隐去密钥和个人数据，保留可核实的文件、时间及测试证据。

## 交付前必须如实说明的边界

- 当前最小聊天页采用临时模式；完整记忆和草稿确认界面属于码道待办，不能提前标记为成品。
- 未配置真实模型 Key 时只提供明确标注的本地支持回复和保留原话的日记草稿；真实模型效果尚需单独验证。
- 当前记忆并发保护适用于单 Node.js 服务进程；多实例部署需要共享锁与持久版本控制。
- 草稿 30 分钟过期指不能再确认，不等于内容已从数据库删除；取消/过期草稿的清理与保留政策仍需落实。
- 危机识别基于词库，存在误报、漏报；关怀提示不应宣传为医疗诊断或自动救援能力。
- 本机启动脚本使用本机 Node/MySQL 路径；完成本机运行不等于已完成跨机器复现。
