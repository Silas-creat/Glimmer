## 建议先交给码道的两个核心任务

### 任务 A：接通可控记忆与续聊

可直接复制给码道：

> 请在“前端参考/chat.html”及必要的独立前端 JS 中完成可控记忆界面。沿用 ui.css 的现有风格，不改后端接口，不引入框架，不在前端存放模型密钥。页面默认临时对话，清楚说明本页上下文刷新后清空。添加“保存对话以便下次继续”的显式开关；未登录时提示登录后才能启用。启用后 POST /api/ai/chat 发送 remember:true，不把临时上下文自动混入已保存历史。关闭后发送 remember:false 和当前临时会话最多16条历史。添加“历史对话”“你记得我什么”“清除对话和记忆”。历史使用 GET /api/ai/messages；记忆使用 GET /api/ai/memory。清除前展示确认说明，用户确认后 DELETE /api/ai/memory；成功后同步清空页面历史和临时上下文。每次请求通过 api.js 的 api()，处理 {code,msg,data}；在请求进行时阻止重复回车，支持中文输入法 Enter 不误发。显示 provider 的真实模式和 degraded 状态，不把本地规则当大模型；渲染 care 求助提示，使用 textContent 显示模型内容。请先给出文件修改清单，再实现并演示：授权保存→刷新续聊→查看记忆→清除→刷新为空、关闭保存后数据库记录不增加。保留真实开发与排错截图。

注意：后端为兼容旧客户端，登录状态下省略 remember 会按原逻辑保存；新的界面必须每次明确发送 true 或 false。临时模式不应恢复旧的持久历史。

任务 A 的状态和实现补充：

- 原始 `createTemporaryChat(api)` 固定发送 `remember:false`、只暴露 send。CodeArts 现已扩展 saved/reset/invalidate，但清除时旧请求仍会回填 history，需按验收报告返修。不要只清空聊天气泡而留下下一次请求会带出的旧 history。保留长回复完整显示、临时上下文每条不超过 2000 UTF-16 单元且不截断代理对。
- 首次使用/新账号默认临时。为实现“授权保存→刷新续聊”，仅可按用户 ID 保存明确选择的模式偏好；未登录、退出或换账号时重新核对，不沿用另一人的同意。开关关闭不等于删除已存历史；页面须区分关闭保存与清除记忆。
- 临时与持久上下文独立。切换、清除、换账号或新会话后，旧异步响应不得重新填回已清空的界面；采用进行中禁用或请求代次检查，清除失败应保留数据并提示失败。
- 保存模式不发送客户端 history（或传空数组），后端自取历史；传入的 history 即使不用，也会先校验。历史第一页为最近 30 条、页内正序，更旧页应向前拼接并按 ID 去重。
- `hasMemory:false` 可能仅代表尚未形成摘要，不代表没有聊天记录。摘要异步产生，界面区分“暂无摘要”和“历史为空”，不要期待聊一轮就出现摘要。
- 所有权限/错误分支先处理 `data.care`。退出登录、模式切换、失败重试和清除后的刷新都要验收。

### 任务 B：接通“整理为私密日记”的确认流程

可直接复制给码道：

> 请为现有聊天页面添加“整理成私密日记”核心流程，保持原视觉风格，不改数据库、不自己拼 SQL。用户选择要整理的内容及日期，默认不读取其他日记；只有用户主动勾选“参考我最近的日记”才传 includeRecentDiaries:true。通过 api('/companion/prepare',{method:'POST',body:{message,date,includeRecentDiaries}}) 获取草稿。展示可编辑正文、日期、私密标识、来源和简洁执行步骤。预览页面必须明确“尚未保存为日记，草稿已暂存服务端”，不能在预览时调用普通日记保存接口。用户点击确认后 POST /companion/drafts/:id/confirm，body 为 {text}；展示真实 diaryId 和返回 url 链接。取消使用 DELETE /companion/drafts/:id。若返回 care 且 draft 为 null，只展示支持提示，不继续生成或保存。正确处理过期、已取消、未登录、跨账号不可访问和当天已有日记的冲突；发生同日冲突不能自动覆盖，允许用户返回选择其他日期重新准备草稿。不得在代码中把 isPublic 改为 true。重复点击只应产生一篇日记，按钮要有明确进行中状态。实现后用两个测试账号验证隐私与幂等，保留真实开发、重构、调试记录。

任务 B 的状态和实现补充：

- 日期按用户所选日历日期传 YYYY-MM-DD，勿直接以 UTC `toISOString().slice(0,10)` 当本地今天。待整理内容最多 2000，预览编辑最多 5000 个 UTF-16 单元，不静默截断；仅发送用户选中的材料。
- prepare 的 provider 是字符串（`local` / `deepseek`），聊天的 provider 是对象，不共用错误的字段判断。来源链接和确认后链接按返回值展示，但仅允许对应站内日记页面，正文/trace 用 textContent。
- 确认成功后显示 `data.url` 和 `diaryId`。请求超时结果不明时，用同一 draftId 查询/重试确认，不能自动再次 prepare；GET 状态可能是 pending/confirmed/cancelled/expired。
- GET 草稿不会自动保存用户的编辑；没有独立“修改草稿”接口。日期修改需重新 prepare，并重新确认参考日记授权。取消是状态变更，不是删除数据库正文；清除聊天也不删除草稿或日记。
- 接口 HTTP 409/410 对应 JSON `code:40900/41000`，不能在 api() 结果中比较 `code===409`。404 不区分不存在与他人草稿，不从前端绕过。
- 用合成账号验收：未授权不读日记、预览不写日记、重复确认幂等、同日冲突不覆盖、他人404、取消/过期、危机停止与模型降级。涉及数据库的测试精确清理自己的随机数据。

## 演示顺序（3 分钟以内）

使用合成演示数据，录像前注明“演示账号”。

1. 20 秒：说明目标用户和问题——一些用户想倾诉，也希望把零散表达整理成可回顾的记录。
2. 40 秒：默认临时聊天，明确选择是否保存；启用后刷新可续聊，查看记忆。
3. 60 秒：授权参考本人日记，生成草稿，修改一句，明确确认，打开真实私密日记。
4. 25 秒：展示同日冲突不会覆盖，另一个账号不能访问；用合成危机用例展示关怀和模型故障降级。
5. 25 秒：展示真实测试结果、架构图和码道实际参与过程，说明能力边界。

不要把页面状态或步骤摘要说成模型的内部思维过程；不把规则模式的输出当作真实模型效果。
