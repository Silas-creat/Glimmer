# 部署工程修复与独立复验

本轮接受 CodeArts 的隔离安装、初始化与回归证据，并继续完成主仓库工程脚本修复。业务基线为 `2112271`；本报告对应在此基础上的工作区改动。原 CodeArts 报告和日志保持原样，以下为独立复核与新增证据。

## 复核结论

- 原安装 143 包、3311 初始化两次、后端健康、两套回归和合成 Key 负向检查均有日志支持。
- 保留的四份补丁仍在 `D:/微光同行/_deploy_repro/checkout-fixed`，不是已全部清理。已只读比对，没有把该目录当成运行环境。
- 原启动补丁用健康响应判断服务归属不充分；本次改为在任何 MySQL 启动/迁移前拒绝已占用后端端口，不复用未知进程。
- 原 8090 监听与脚本哈希不等于代理通过；本轮补验真实启动器的 8092 → 3002 健康请求。
- 原 `D:/mysql/data` 指纹未证明属于实际 3307。仅保留 `.env` 哈希与进程身份一致的结论，不宣称库表内容零写入已验证。
- EPERM 和 MySQL 不监听的历史根因不能直接归为文件监视。当前仓库内独立数据目录实际可运行；绝对中文 datadir 参数未成功，改为在已核对的数据目录中启动并传 `--datadir=.` 后成功。

## 主仓库变化

1. `setup/start.js` 读取 `.env`，系统环境变量优先；校验端口、拒绝后端端口占用；支持 `MYSQL_BASEDIR` / `MYSQL_DATA_DIR`，只拉起已初始化的本地库；`--no-defaults` 位于首参，绑定 loopback，关闭 mysqlx；不初始化和重置认证。
2. 迁移失败或数据库不健康即停止，关闭自己刚创建的后端。正常信号退出也关闭本次后端；强制终止进程仍可能绕过退出钩子。代理指向实际 `PORT`，`/api.js` 正常静态服务，畸形编码、NUL 和目录穿越被拒绝。
3. 三个检查器采用仓库相对路径。安全检查缺失输入直接失败；前端实际验证全局 API 函数契约和外链 JS 语法；零 HTML 失败。runtime 检查必须显式指定后端及合成账号，限制同 origin 并禁止重定向，不再默认访问现有 3000。
4. `.gitattributes` 固定四个 shell 脚本为 LF。当前 Git 对象与工作区本来就是 LF，但 `core.autocrlf=true` 的旧版 archive 输出出现 CRLF；`git archive --worktree-attributes` 使用新规则后四份文件均无 CRLF。
5. 修正部署指南的版本、工作目录、模型 URL、启动顺序、检查命令和证据边界。根 README 的默认前端端口恢复为代码实际的 8080，说明 8081 是常见开发端口。
