# 安装器保护与仓库整理验收

本轮按用户要求修复 `setup/install.js` 的实例识别和认证保护，整理目录并准备上传 `Silas-creat/Glimmer`。此前启动器与检查器修复一并纳入交付，陪伴业务源码保持不变。使用预装 MySQL 8.4.13，真实模型仍未配置。

## 安装器行为

- `--check` 只检查文件与环境，不安装依赖、不连接数据库、不启动进程、不写配置。它不证明数据库认证有效。
- 默认新安装只创建独立实例：同时选择空闲端口与不存在的数据目录；显式端口被占用或指定目录已存在则拒绝，不尝试空密码或常见密码。
- 初始化使用 `--no-defaults` 和目录内相对路径，启动仅绑定 loopback 并关闭 mysqlx。Windows 加 `--no-monitor`，让失败清理针对实际服务进程。
- 对本次新目录的 `auto.cnf` UUID 与服务器 `@@server_uuid`、端口核对后，才设置随机初始密码。凭证通过内存连接使用，不放入命令行、不打印；采用 MySQL 默认认证插件，实测为 `caching_sha2_password`。
- `.env` 独占创建，不覆盖。已有配置时默认退出；显式 `--use-existing` 才按实际 host/user/port/database 建表和迁移，不改认证。由安装器生成的 UUID 会继续核对；手工配置可以加入已核实的 UUID。
- 不自动运行 `seed-demo.js`，该脚本会重建部分聊天数据。安装只准备表结构和基础群聊房间。
- 失败时停止本轮创建的实例，保留配置和数据目录供排查。如果初始密码设置本身失败，保存的随机密码可能尚未生效，应先核对状态，不能直接假定 `--use-existing` 可恢复。
