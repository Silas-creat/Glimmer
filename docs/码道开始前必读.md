## 先确定编辑的是哪份项目

当前整理后的开发仓库是 **Glimmer**。本机路径为 `D:/微光同行/Glimmer`；在其他电脑以实际克隆目录为准。2026-11-13 核对的整理提交为 `3086f72`。以后有新提交或未提交修改，应记录实际版本，不能一直照抄这个编号。

| 目录 | 用途 |
|---|---|
| `Glimmer/` | 当前整理后的源码和文档仓库，码道建议在这里继续开发 |
| 上一级 `二十三稿/` | 原开发目录，已包含二十四稿增量；目录名不代表代码仍是合并前版本 |
| 上一级 `24稿/` | 队友发来的原始包，只作来源参考，不能整包覆盖当前版本 |
| 上一级 `.runtime/` | 原机器运行环境、历史测试日志和合并前快照，不随仓库交付 |

核对时，Glimmer 的前端业务文件、后端 src/scripts/sql 与已验收的合并版一致（前端 README 为整理后的说明）。这说明代码基线一致，不代表 Glimmer 已完成独立启动或异机验收。

原机器的 `D:/微光同行/启动项目.bat` 调用 `.runtime/start.cjs`，仍指向 `二十三稿`。只修改 Glimmer 后访问原来的 8080，可能仍在验收旧目录。Glimmer 的 `setup/start.js` 遇到 3000 已占用会复用后端，因此也不能仅凭“启动成功”判断服务来自哪个目录。联调前核对前端实际服务目录、后端进程工作目录/启动命令和数据库；需要切换时只处理已确认身份的本项目进程，不杀掉所有 Node/MySQL，不重建已有数据库。本文更新没有切换运行服务。
