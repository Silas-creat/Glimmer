## 建议先交给码道的两个核心任务

### 任务 A：接通可控记忆与续聊

可直接复制给码道：

> 请在“前端参考/chat.html”及必要的独立前端 JS 中完成可控记忆界面。沿用 ui.css 的现有风格，不改后端接口，不引入框架，不在前端存放模型密钥。页面默认临时对话，清楚说明本页上下文刷新后清空。添加“保存对话以便下次继续”的显式开关；未登录时提示登录后才能启用。启用后 POST /api/ai/chat 发送 remember:true，不把临时上下文自动混入已保存历史。关闭后发送 remember:false 和当前临时会话最多16条历史。添加“历史对话”“你记得我什么”“清除对话和记忆”。历史使用 GET /api/ai/messages；记忆使用 GET /api/ai/memory。清除前展示确认说明，用户确认后 DELETE /api/ai/memory；成功后同步清空页面历史和临时上下文。每次请求通过 api.js 的 api()，处理 {code,msg,data}；在请求进行时阻止重复回车，支持中文输入法 Enter 不误发。显示 provider 的真实模式和 degraded 状态，不把本地规则当大模型；渲染 care 求助提示，使用 textContent 显示模型内容。请先给出文件修改清单，再实现并演示：授权保存→刷新续聊→查看记忆→清除→刷新为空、关闭保存后数据库记录不增加。保留真实开发与排错截图。

注意：后端为兼容旧客户端，登录状态下省略 remember 会按原逻辑保存；新的界面必须每次明确发送 true 或 false。临时模式不应恢复旧的持久历史。

### 任务 B：接通“整理为私密日记”的确认流程

可直接复制给码道：

> 请为现有聊天页面添加“整理成私密日记”核心流程，保持原视觉风格，不改数据库、不自己拼 SQL。用户选择要整理的内容及日期，默认不读取其他日记；只有用户主动勾选“参考我最近的日记”才传 includeRecentDiaries:true。通过 api('/companion/prepare',{method:'POST',body:{message,date,includeRecentDiaries}}) 获取草稿。展示可编辑正文、日期、私密标识、来源和简洁执行步骤。预览页面必须明确“尚未保存”，不能在预览时调用普通日记保存接口。用户点击确认后 POST /companion/drafts/:id/confirm，body 为 {text}；展示真实 diaryId 和返回 url 链接。取消使用 DELETE /companion/drafts/:id。若返回 care 且 draft 为 null，只展示支持提示，不继续生成或保存。正确处理过期、已取消、未登录、跨账号不可访问和当天已有日记的冲突；发生同日冲突不能自动覆盖，允许用户返回选择其他日期重新准备草稿。不得在代码中把 isPublic 改为 true。重复点击只应产生一篇日记，按钮要有明确进行中状态。实现后用两个测试账号验证隐私与幂等，保留真实开发、重构、调试记录。

## 后续较独立的任务

1. **首页主入口**：在群聊卡片上方添加明显的“和小陪聊聊”入口及一句用途说明，AI 入口不再只在好友页。保持群聊原路径可用，按钮语义、键盘焦点和文字对比度需验证。
2. **功能与隐私说明**：解释临时聊天、账号历史、长期摘要、私密日记之间的区别；说明 AI 可做生活记录和情绪支持，不用于医学诊断；提示用户可以查看和清除记忆。
3. **当前版本自检修复**：将 smoke-test.js 的旧前端绝对路径替换成当前相对目录；更新 check-frontend.js 对实际全局 api() 形态的检查。测试应发现真实断链，不要通过删除断言来制造“全部通过”。
4. **复现与部署**：将根目录本机启动器依赖的 Node/MySQL 路径改为可配置，在干净目录或另一台机器按 README 执行安装、迁移、启动与核心测试。运行参赛测试使用 Node 24 LTS。保存实际命令、问题、修复和验证截图。

过程记录使用 `码道交互记录模板.md`，接口细节见 `陪伴核心接口契约.md`，逐项交付优先级见 `参赛评分对齐与交付计划.md`。模板本身不属于码道使用证据。

## 演示顺序（3 分钟以内）

使用合成演示数据，录像前注明“演示账号”。

1. 20 秒：说明目标用户和问题——一些用户想倾诉，也希望把零散表达整理成可回顾的记录。
2. 40 秒：默认临时聊天，明确选择是否保存；启用后刷新可续聊，查看记忆。
3. 60 秒：授权参考本人日记，生成草稿，修改一句，明确确认，打开真实私密日记。
4. 25 秒：展示同日冲突不会覆盖，另一个账号不能访问；用合成危机用例展示关怀和模型故障降级。
5. 25 秒：展示真实测试结果、架构图和码道实际参与过程，说明能力边界。

不要把页面状态或步骤摘要说成模型的内部思维过程；不把规则模式的输出当作真实模型效果。
