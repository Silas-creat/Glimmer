# 微光同行：参赛核心能力设计

用户授权：先确定主要方向，实施后端复杂能力，提供可交给华为云码道完成的核心页面接入任务。

方向：有可控记忆的情绪陪伴。用户表达 → 按明确授权读取本人的近期记录 → 整理私密日记草稿 → 本人确认 → 保存并返回真实结果。临时聊天和持续记忆分开；危机关怀不依赖模型成功。定位为生活记录与情绪支持，不做诊断或治疗结论。

## 官方约束

西安邮电大学站官网要求使用华为云码道作为核心 AI 编程工具，并提交真实核心开发、重构或排错记录。这里的工作记录为 Codex 辅助贡献；后续码道需实际承担核心功能开发与集成，不能把本次记录描述为码道产出。初赛提交截止 2026-11-18，内部交付目标 11-17。

## 范围与接口

1. 保留 Express / MySQL / 原生前端，不增加框架依赖。
2. 加固现有 `/api/ai/chat`：兼容原响应；增加 `remember:false` 临时模式、有限历史输入，临时模式不读取或写入长期记忆；明确返回 `saved`、`provider`、`care`。已登录旧客户端省略 remember 时保持原有保存行为。聊天与清除同一用户记忆串行化，防止在途写入恢复已清除内容。
3. 现有历史、记忆查看与清除 API 保留。模型失败时返回明确降级状态，危机关怀仍可达；不假装本地规则为真实大模型。记忆作为不可信背景资料，不能覆盖系统指令。
4. 新增 `/api/companion/prepare`，请求 `{message,date,includeRecentDiaries}`；必须登录，message 1–2000 字，日期为有效 YYYY-MM-DD，includeRecentDiaries 仅显式 true 时取本人近期最多 3 篇日记。返回 `{draft,trace}`。草稿含 id、date、text、sources、provider、status、expiresAt；30 分钟过期。没有真实模型时规则整理并显式标注。
5. `GET /api/companion/drafts/:id` 仅本人可读；`POST /api/companion/drafts/:id/confirm` 请求 `{text?}`，最多 5000 字。事务内验证归属、状态和期限，保存 `is_public=0` 的日记并返回真实 diaryId 与链接。一天已有日记则 409，绝不覆盖。重复确认已完成草稿返回相同记录，不重复创建。`DELETE /api/companion/drafts/:id` 取消未确认草稿。
6. 审核独立识别危机与广告/攻击。关怀不抵消违规限制；公开内容可按规则限制传播，但同时返回 care。模型失败仍返回 care。不要宣称词库覆盖全部危机表达。
7. 本次只做聊天页面最小安全接线：去掉浏览器密钥与模型直连，走服务端 API，标明临时模式，避免双重发送并展示 care。完整历史/记忆控制/草稿确认 UI 留给码道接入，提供接口契约和测试步骤。

## 验收

- 临时聊天前后数据库聊天记录数不变；持续聊天可恢复，清除后无残留摘要/历史。
- 独立合成账号测试草稿预览不写 diaries、确认才写且仅私密、重复确认幂等、跨账号 404、未登录 401、同日冲突不覆盖、过期/取消不可执行。
- 普通难过、明确危机、危机加广告/攻击、单独广告等用例；危机提示在模型故障时仍存在。
- 不触发付费模型测试；本地模式与本地受控模型桩分别验证接口契约，真实模型效果标为未验证。
- 修改前保存源码快照；这是非 Git 目录，不创建额外仓库或提交。由独立代理审查差异，修复重要发现后再交付。
