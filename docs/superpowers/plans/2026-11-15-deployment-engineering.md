# 部署工程修复与独立复验计划

**目标：** 将 CodeArts 已验证的工程脚本修复纳入主仓库，修正端口归属判断并补验真实启动与前端代理。

**依据：** `.codeartsdoer/specs/deploy_repro_hardening/` 与用户“没有很大问题就继续下一步优化”的授权。业务版本基线为 `2112271`。

**约束：** 不修改陪伴业务源码、不更改现有 `.env`、不连接现有 3307；模型配置继续推迟。历史报告与日志原样保留。安装器认证流程、依赖大版本升级不纳入本次修复。

## 实施与验证

1. 只读复核 CodeArts 日志与保留补丁；区分已证明的结果、推断的原因与未验收项。
2. 检查器：修正三个脚本的相对路径，明确 PASS/WARN/SKIP/FAIL；缺失前端不能绕过密钥检查；实际检查当前顶层函数式 API 契约。先运行能复现缺陷的回归，再实现修复。
3. 启动器：配置与后端环境变量优先级一致；非法端口提前拒绝；占用后端端口在任何启动/迁移前拒绝；只拉起明确配置的已初始化本地 MySQL；迁移或数据库健康失败终止；代理使用配置端口。使用隔离测试覆盖副作用边界。
4. `.gitattributes` 固定 shell 为 LF；核对当前 Git 对象与工作区，不把历史导出物 CRLF 直接归因于 `git archive`。
5. 新建临时隔离副本，独立安装依赖和初始化随机密码的测试数据库。通过真实 `setup/start.js` 启动新后端与前端，核对直连和代理健康、静态脚本哈希，执行两套完整回归和边界验收。
6. 核对原 `.env` 与业务文件哈希、现有服务身份；停止并清理本轮确切创建的实例。修正文档并记录新证据，未执行项保持未验证。

验证入口：`node --test setup/start.test.js`、检查器专用测试、`npm test`、`node scripts/check-frontend.js`、`npm run test:competition`、`npm run test:merge24`。所有数据库集成命令仅在新隔离配置下执行。
