# 2. 组件定位

## 2.1 核心职责

本组件负责判定陪伴页当前会话中的内容归谁所有，并在“本页匿名上下文”与“曾登录账号遗留上下文”之间划出可观察、可测试的边界。

## 2.2 核心输入

1. 当前身份来源：同源存储中的账号标识、凭证、账号显示信息，以及同源其他页面发出的 `storage` 变更通知。
2. 用户操作：输入框文本、点击“说”、点击历史/记忆/清除/草稿入口、关闭面板、开启或关闭保存开关。
3. 页面内存状态：本页已产生的对话轮次、面板打开状态、草稿/摘要/历史读取结果、发送进行中归属。
4. 后端响应：`/ai/chat`、`/auth/me`、`/ai/messages`、`/ai/memory`、`/companion/*` 的成功、失败、401/40100、迟到与网络错误。
5. 页面初始化输入：页面加载时可见的 token、user 与保存偏好。
6. 刷新事件：用户重新加载页面后重新初始化的空页面。

## 2.3 核心输出

1. 会话分类结果：匿名游客、已登录、待隔离（内部判定，用户不需要看到术语本身）。
2. 面向用户的回复气泡、状态提示、保存状态说明与受限入口登录提示。
3. 请求输出：是否发出 `/ai/chat`、以 `remember:false` 发送、本页 `history` 内容、不发出受保护数据请求。
4. 清理输出：真实退出/换号/失效时清空旧账号气泡、草稿、摘要、面板、输入与在途归属。
5. 非输出（禁止产生）：不把游客消息持久化、不把旧账号内容带进游客页、不因游客合法上下文弹出“登录状态已失效”。

## 2.4 职责边界与非目标

**本组件负责：**

1. 本页匿名上下文与旧账号遗留上下文的可观察区分。
2. 游客连续多轮发送、失败重试、受限入口提示、关闭面板后继续聊天的行为一致性。
3. 真实退出登录/换号/token 移除时旧账号内容的隔离不被削弱。
4. 对应的正式回归用例与证据边界说明。

**本组件不负责（本轮非目标）：**

1. 不修改后端 `后端源码/src/**`、`sql/**`、`.env`，不改变任何接口契约、状态码或 `remember` 语义。
2. 不新增游客账号、匿名身份、服务端游客存储或游客持久化。
3. 不修改数据库端口/结构，不重建数据，不执行 `initdb`、`DROP`、`TRUNCATE`、`ALTER`。
4. 不引入前端框架、构建工具或状态管理库；保持原生 HTML/JS/CSS。
5. 不调整模型配置、不查找其他项目凭证、不打印密钥或真实用户内容。
6. 不重写身份核验票据体系，不删除 `isolateSignedOutContext`，不以“删掉安全检查”换取游客通过。
7. 不改变既有关怀渲染、草稿幂等、清除语义、发送锁归属与 2000 字上限。
8. 不把本地规则回复描述为真实大模型效果；`configured=false` 的事实必须如实保留。

# 3. 领域术语

**本页匿名上下文（guest-local context）**
: 指未登录游客在当前页面生命周期内产生的、仅存在于本页内存的对话内容与页面状态；它不以任何账号身份产生，刷新后即消失。

**旧账号遗留上下文（legacy account context）**
: 指当前页面曾绑定账号（或仍残留账号标识/凭证/保存模式），或页面内存中存在只能由受保护接口产生的账号专属结果（草稿、记忆摘要、账号历史）时，属于旧账号的内容与状态。

**上下文归属**
: 指判定一段内容“属于本页匿名游客”还是“属于某个账号”的依据。归属必须由内容来源与身份痕迹决定，禁止仅由内容是否存在决定。

**身份痕迹**
: 页面内是否残留账号标识、凭证、保存模式、账号绑定事实等可证明“曾/仍与账号关联”的痕迹。

**账号专属内容**
: 只能通过需要登录的接口获得或产生的业务结果，包括草稿及其归属材料、记忆摘要、账号历史列表；游客受限入口不会产生这些结果。

**页面级通用状态**
: 游客与登录账号都会产生的界面状态，包括本页对话轮次、当前面板类型、发送锁、输入框文本、停止轮次标记；它们本身不携带账号归属。

**受限入口**
: 历史对话、记忆、清除记录、生成草稿等需要登录才能执行读取或写入的入口。

**失效隔离**
: 在凭证被移除、核验返回 401、后端返回登录失效或换号时，先清空旧账号内容并使旧在途响应失效，再转为匿名临时会话的动作。

**待隔离会话**
: 页面内存在身份痕迹或账号专属内容，但当前没有有效凭证；在允许任何新动作前必须先完成失效隔离。

# 4. 角色与边界

## 4.1 核心角色

匿名游客：未登录进入陪伴页、希望连续临时聊天、不要求保存的个人用户。

登录用户：已登录并使用保存/历史/记忆/草稿能力的个人用户。

退出或换号用户：在本页或同源其他页面完成退出登录、切换账号、凭证失效的用户。

## 4.2 外部系统

陪伴对话服务：接收 `/ai/chat`，区分 `remember:false` 临时消息与 `remember:true` 保存消息。

身份服务：提供 `/auth/me` 核验当前凭证与账号。

历史与记忆服务：提供 `/ai/messages`、`/ai/memory`，仅对登录账号返回数据。

草稿服务：提供 `/companion/prepare`、`/companion/drafts/:id`（GET/DELETE）与确认接口，仅对登录账号生效。

同源页面存储：保存 token、user 与保存偏好，并通过 `storage` 事件通知其他同源页面。

# 5. DFX 约束

## 5.1 性能

1. 会话归属判定必须是本地同步判定，不得为判定而发起任何网络请求；游客连续发送时不得新增 `/auth/me` 调用。
2. 归因判定不得引入轮询、定时器或额外渲染循环。
3. 游客连续 3 轮发送的请求次数必须恰为 3 次，不得出现判定导致的重试放大。

## 5.2 可靠性

1. 合法游客上下文被误隔离的次数必须为 0：同一游客页连续多轮、失败重试、受限入口点击、关闭面板后继续聊天均不得触发失效隔离。
2. 真实失效隔离不得漏触发：凭证被移除、换号、核验 401、后端 40100 时，旧账号内容清空次数必须为 100%。
3. 隔离后页面必须稳定处于匿名临时会话，发送按钮可用，不出现永久发送锁。
4. 旧账号在途响应返回时不得写入游客页面、不得回填游客输入。

## 5.3 安全性

1. 游客消息禁止以 `remember:true` 发送；禁止写入账号历史、记忆、草稿或保存偏好。
2. 旧账号的气泡、草稿、摘要、账号历史、材料禁止出现在游客页面。
3. 游客受限入口禁止发出需要登录的读取/写入请求。
4. 提示、日志、截图与测试输出禁止包含 token、Authorization、密钥、真实手机号或真实用户内容；一律使用合成文本。

## 5.4 可维护性

1. 上下文归属判据必须集中在一处可观察定义中，不得在多处各自复制一套不一致的判断。
2. 归属判据必须可被正式回归用例直接观察（通过请求计数、页面文本、`state` 既有字段与 DOM），不得依赖修复后新增的内部符号。
3. 每个归属分支必须有唯一可解释的结果，不得用“内容非空”这种模糊条件代替来源判定。

## 5.5 兼容性

1. `/ai/chat`、`/auth/me`、`/ai/messages`、`/ai/memory`、`/companion/*` 的 URL、方法、body 字段与状态码语义保持不变。
2. `前端参考/chat-session.js` 的 `remember:false`+本页 `history` 与 `remember:true`+空 `history` 语义保持不变。
3. 既有 `state` 字段名与类型、既有按钮文案、既有测试 harness 结构保持不变。

# 6. 核心能力

## 6.1 R9 · 本页匿名上下文的归属与隔离边界

### 6.1.1 业务规则

1. **归属必须由来源决定，不得由内容存在性决定**：当系统判定当前页面是否存在旧账号遗留内容时，应当依据身份痕迹与账号专属内容，不得仅因本页存在对话轮次或面板打开状态就判定为旧账号内容。
   - 状态前置：当前无有效凭证。
   - 可观察行为：同一页面已有游客对话或已打开游客受限面板时，判定结果仍为匿名游客。
   - 失败/过期路径：若判定把页面级通用状态当作账号遗留，则属于缺陷，必须修正判据。
   - UI 提示：不得因此显示“登录状态已失效”。
   - 非目标：不要求新增持久化字段，不要求改变会话对象结构。
   a. 验收条件：[无 token、无 user，游客已发送 1 条且 `turns.length > 0`] → [会话仍为匿名游客；下一次发送不被隔离]。

2. **身份痕迹的判定范围**：系统应当把以下任一情况视为存在身份痕迹：页面仍残留账号标识、页面仍残留凭证、当前处于保存模式、页面曾成功绑定账号且尚未完成隔离。
   - 状态前置：页面可能来自“曾登录后退出的同源标签页”。
   - 可观察行为：上述痕迹存在时，页面不得被当作纯匿名游客直接发送。
   - 失败/过期路径：痕迹存在但凭证已空时，必须先隔离再允许游客发送。
   - UI 提示：隔离时使用统一失效文案。
   - 非目标：不把“本页对话轮次”“面板类型”“输入框文本”计入身份痕迹。
   a. 验收条件：[登录 A 后 token 被移除、页面仍有 A 气泡] → [识别为待隔离并清空 A 内容，而不是当游客直接发送]。

3. **账号专属内容的判定范围**：系统应当把以下任一情况视为存在账号专属内容：页面存在草稿及其归属材料、存在记忆摘要、存在账号历史列表。上述内容只能由需要登录的接口产生。
   - 状态前置：当前无有效凭证，页面可能残留上一次读取结果。
   - 可观察行为：存在上述内容时，页面不得被当作纯匿名游客直接发送；必须先隔离。
   - 失败/过期路径：隔离必须清空这些内容及其面板展示。
   - UI 提示：清理后显示已转为临时对话，不显示旧摘要/草稿。
   - 非目标：不把错误气泡、临时对话轮次、面板标题当作账号专属内容。
   a. 验收条件：[游客页从未调用受保护接口] → [`memorySnapshot`、`historyItems`、`draft` 均为空，不构成隔离理由]。

4. **页面级通用状态不构成归属证据**：系统禁止把本页对话轮次、当前面板类型、发送锁、停止轮次标记、输入框文本作为“存在旧账号内容”的判据。
   - 状态前置：游客已聊天或已打开受限面板。
   - 可观察行为：这些状态无论取何值，都不触发失效隔离；游客可继续发送。
   - 失败/过期路径：若因此触发隔离，页面不得清空合法匿名聊天。
   - UI 提示：不得出现“登录状态已失效”。
   - 非目标：不要求删除这些状态字段，只要求不把它们当作归属证据。
   a. 验收条件：[游客 `turns.length = 6` 且 `panelKind = 'history'`] → [分类仍为匿名游客；后续发送仍发出 `remember:false`]。

5. **游客同一页面必须支持连续多轮**：当匿名游客在同一页面连续发送时，系统应当每轮恰好发出一次 `/ai/chat`，请求体 `remember:false`，并携带本页已完成的上下文。
   - 状态前置：无 token、无 user；页面未刷新；发送锁空闲。
   - 可观察行为：第 1 轮 `history` 为空；第 2 轮 `history` 含前 1 轮的用户与回复；第 3 轮 `history` 含前 2 轮共 4 条；最多保留最近 16 条。
   - 失败/过期路径：任一后续轮次未发出请求、被隔离清空或改为 `remember:true`，均判不满足。
   - UI 提示：聊天区保留全部游客轮次，状态区显示“本次未保存/临时对话刷新后清空”；不得显示“登录状态已失效”。
   - 非目标：不改变 `chat-session.js` 的历史截断与 2000 字上限；不把游客上下文写入服务端。
   a. 验收条件：[游客连续发送 3 条并等待每轮回复] → [`/ai/chat` 恰好 3 次；`remember` 均为 `false`；`history.length` 依次为 0、2、4；无 `/auth/me`；`turns.length = 6`；聊天区含 3 条用户文本]。

6. **游客发送失败后的重试必须真正再次请求**：当游客首条发送失败、系统把原文恢复到输入框后，用户再次点击发送时，系统应当真正发出新请求，而不是把点击吞掉或再次触发隔离。
   - 状态前置：游客会话；首条 `/ai/chat` 返回业务错误或网络失败；输入框已恢复原文；发送按钮已恢复可用。
   - 可观察行为：第二次点击产生第 2 次 `/ai/chat`；`remember:false`；成功后显示回复并清空输入；失败后仍保留原文且按钮可用。
   - 失败/过期路径：不得因上一轮失败残留的轮次而把第二次点击判为“登录失效”；不得重复追加同一条用户气泡。
   - UI 提示：失败时显示可恢复错误；成功时显示回复与“本次未保存”；不得显示“登录状态已失效”。
   - 非目标：不改变错误码映射与关怀展示；不改变发送锁的单飞语义。
   a. 验收条件：[游客首条失败，输入恢复为原文，再次点击“说”] → [`/ai/chat` 调用数从 1 增至 2；第二轮 `remember:false`；成功后出现回复；无 `/auth/me`]。

7. **游客受限入口只提示登录，不得清空匿名对话**：当游客在已有匿名聊天后打开历史、记忆、清除或草稿入口时，系统应当只提示需要登录，不得执行隔离、不得清空匿名内容、不得发出受保护数据请求。
   - 状态前置：游客已至少完成 1 轮聊天；存在本页匿名上下文。
   - 可观察行为：面板打开并显示对应登录提示；聊天区、`turns` 保持不变；不发出 `/ai/messages`、`/ai/memory`、`/companion/*`。
   - 失败/过期路径：若入口判定先把游客误判为待隔离，则属于缺陷；不得以“先清空再提示”解释。
   - UI 提示：按入口分别显示“登录后才能查看历史对话”“登录后才能查看记忆”“登录后才能清除记录”“登录后才能生成草稿”。
   - 非目标：不新增游客可用历史/记忆/草稿；不绕过登录鉴权；不改变登录用户的入口行为。
   a. 验收条件：[游客发送 1 条后点击“历史对话”] → [面板含“登录后才能查看历史对话”；聊天区仍含该条游客文本；`turns.length` 不变；无 `/ai/messages`]。

8. **关闭受限面板后必须能继续聊天**：当游客关闭受限面板后，系统应当保留匿名上下文，并允许继续以 `remember:false` 发送。
   - 状态前置：游客已通过受限入口看到登录提示并关闭面板。
   - 可观察行为：关闭后面板隐藏；聊天区与 `turns` 保持；下一次发送产生新 `/ai/chat`；仍不请求 `/auth/me`。
   - 失败/过期路径：关闭动作不得触发清理、不得推进导致旧内容失效的代次。
   - UI 提示：保持“本次未保存”状态。
   - 非目标：不要求关闭面板后自动重新打开聊天；不改变面板关闭的既有代次语义。
   a. 验收条件：[游客聊天后打开历史并关闭面板，再发送 1 条] → [`/ai/chat` 总数为 2；聊天区含两条游客文本；无受保护请求]。

9. **游客刷新后必须清空且不得恢复**：当匿名游客刷新页面时，系统应当丢弃本页匿名上下文，不读取账号历史/记忆，不恢复匿名消息。
   - 状态前置：游客已完成至少一轮或多轮聊天。
   - 可观察行为：新页面仅有初始问候；`turns` 为空；无 `/ai/messages`、`/ai/memory`；再次发送仍为 `remember:false`；本地存储无新增持久化键。
   - 失败/过期路径：不得把刷新前的匿名消息当作账号内容或游客持久化内容恢复。
   - UI 提示：显示初始问候与“临时对话 · 本页保留上下文，刷新后清空”。
   - 非目标：不新增游客本地存储；不改变 `chat-session.js`。
   a. 验收条件：[游客连续 3 轮后重新初始化空页面] → [`turns.length = 0`；聊天区仅含初始问候；无历史/记忆请求；再次发送 `remember:false`]。

10. **真实退出登录、换号与凭证移除仍必须隔离**：当登录账号的凭证被移除、页面检测到账号切换、核验返回 401 或后端返回 40100 时，系统应当先清空旧账号的内容并使其在途响应失效，再转为匿名临时会话。
    - 状态前置：页面曾绑定账号（或仍残留身份痕迹/账号专属内容）。
    - 可观察行为：旧气泡、草稿、摘要、面板、输入、发送锁归属被清空；随后游客发送为 `remember:false`；旧响应不落地。
    - 失败/过期路径：隔离未完成前不得允许发送；不得保留旧账号输入文本作为游客消息。
    - UI 提示：显示“登录状态已失效，已转为临时对话；本次不保存”。
    - 非目标：不删除服务端历史/记忆；不改变 `settings.html` 的退出实现。
    a. 验收条件：[登录 A 已聊天并有草稿，token 被移除] → [A 气泡与草稿消失；页面为临时会话；游客发送 `remember:false`]。

11. **换号后不得把旧账号内容或匿名内容带入新账号**：当页面检测到账号从 A 切到 B，或游客转登录时，系统应当清空上一段会话内容并重新绑定新身份，不得把上一段内容当作新账号历史。
    - 状态前置：A 页面有内容，或游客页面有匿名内容。
    - 可观察行为：聊天区清空上下文；保存模式不自动开启；不发出携带旧上下文的 `remember:true` 请求。
    - 失败/过期路径：切换失败不得保留旧内容继续发送。
    - UI 提示：显示“检测到账号变化，已回到临时对话”或等价提示。
    - 非目标：不改变登录页与保存偏好键。
    a. 验收条件：[A 页面有气泡与草稿 → 切到 B] → [页面无 A 内容；`state.uid === 'B'`；不发出 A 的请求]。

12. **提示文案与禁止项**：系统必须保持既有提示语义：游客未保存为“本次未保存；临时对话刷新后清空”，失效隔离为“登录状态已失效，已转为临时对话；本次不保存”，受限入口为“登录后才能…”。系统禁止：
    - 清空合法匿名聊天；
    - 把游客消息以 `remember:true` 发送；
    - 把旧账号内容带进游客页面；
    - 把匿名内容写入历史/记忆/草稿/保存偏好；
    - 为让游客通过而删除或跳过真实失效隔离；
    - 把游客状态显示为“已保存到本人账号”；
    - 把本地降级回复描述为真实模型效果。
    a. 验收条件：[游客连续聊天、失败重试、打开受限入口、刷新、退出/换号] → [以上禁止项均无发生；提示文案语义一致]。

### 6.1.3 异常场景

1. **游客第 2 轮被误判为登录失效**
   a. 触发条件：无登录游客已发送 1 条，`turns` 非空，未刷新再发送。
   b. 系统行为：保持匿名游客分类，正常发出第 2 次请求；不得执行失效隔离。
   c. 用户感知：聊天与输入保留，得到回复；不再出现“登录状态已失效”。

2. **游客首条失败后重试被吞掉**
   a. 触发条件：首条 `/ai/chat` 失败，原文已恢复到输入框，用户再次点击发送。
   b. 系统行为：释放上一轮发送锁，按匿名游客发出第 2 次请求。
   c. 用户感知：按钮可用，原文不被错误清空；成功时出现回复。

3. **游客打开历史/记忆/清除/草稿后匿名对话被清空**
   a. 触发条件：游客已有聊天，点击任一受限入口。
   b. 系统行为：只打开面板并提示登录；不隔离、不请求受保护数据。
   c. 用户感知：匿名聊天仍在；关闭面板后可继续聊天。

4. **游客在面板打开状态下发送**
   a. 触发条件：游客打开受限面板但尚未关闭，继续点击发送（模拟 DOM 场景，浏览器未验证）。
   b. 系统行为：按匿名游客发送；面板类型不构成隔离理由。
   c. 用户感知：请求正常发出；不出现登录失效提示。

5. **游客刷新后误恢复匿名内容**
   a. 触发条件：游客聊天后刷新页面。
   b. 系统行为：丢弃内存上下文，不读取历史/记忆。
   c. 用户感知：只剩初始问候，可重新临时聊天。

6. **真实退出后旧内容仍可见**
   a. 触发条件：登录 A 的 token 被移除或账号切换。
   b. 系统行为：先隔离 A 的气泡、草稿、摘要、面板与在途归属，再转临时会话。
   c. 用户感知：A 内容消失；明确提示已转临时对话。

7. **旧账号响应迟到**
   a. 触发条件：A 的发送/读取响应在隔离后返回。
   b. 系统行为：丢弃响应，不写入游客页面，不回填输入，不解锁新发送。
   c. 用户感知：游客页面只显示自己的内容。

8. **游客快速双击**
   a. 触发条件：游客在请求进行中连续点击两次。
   b. 系统行为：同步占位拦截第二次，只发 1 次。
   c. 用户感知：只出现一条消息与一个回复，按钮最终恢复可用。

# 7. 数据约束

> 本章只描述页面会话归属的逻辑约束，不定义存储结构、数据库字段或实现变量。

## 7.1 页面会话归属

1. **会话类型**：取值必须明确属于“匿名游客”“已登录”“待隔离”之一；不得用模糊布尔值表达。
2. **身份痕迹**：必须可判定是否存在账号标识、凭证、保存模式或账号绑定事实。
3. **账号专属内容标志**：必须可判定是否存在草稿、记忆摘要、账号历史列表。
4. **页面级通用状态**：必须与身份痕迹、账号专属内容分开记录；禁止作为归属判据。
5. **隔离完成标志**：只有旧内容与在途归属全部清理后，才可标记隔离完成。
6. **刷新语义**：刷新后身份痕迹与页面级通用状态均重新初始化；匿名上下文不得恢复。

## 7.2 本页匿名上下文

1. **账号归属**：必须为空；不得归到任何账号。
2. **存在范围**：只允许本页内存；不得写入任何持久化键。
3. **发送标志**：每轮必须为 `remember:false`。
4. **上下文范围**：只允许本页已完成轮次，最多最近 16 条；不得读取服务端历史或长期记忆。
5. **轮次完整性**：每轮恰好产生 1 个用户气泡与 1 个成功回复气泡；错误气泡不计入上下文。
6. **受限入口影响**：打开/关闭受限入口不得改变匿名上下文的轮次与发送能力。

## 7.3 旧账号遗留上下文

1. **识别依据**：必须来自身份痕迹或账号专属内容；不得仅由对话轮次或面板类型推出。
2. **清理范围**：气泡、轮次、草稿、材料、历史、摘要、面板、关怀、输入、发送归属与在途请求归属。
3. **清理时机**：凭证移除、账号切换、核验 401、后端 40100、要求登录的入口检测到待隔离状态。
4. **清理后状态**：必须为匿名临时会话，发送按钮可用。
5. **在途请求**：清理后可继续网络传输，但结果不得写入页面、不得回填输入、不得解锁新发送。

# 8. 保留项、不得触碰文件与契约

## 8.1 必须保留的 R1–R8 行为

# 附录 A · 根因与现状核对（只读事实，不构成实现方案）

> 行号以本轮 `前端参考/chat-companion.js`（1745 行、哈希 `854EEB95…`）为准。

## A.1 现象

1. 无登录进入 `chat.html`，第 1 条正常得到回复。
2. 不刷新发送第 2 条：不发出 `/ai/chat`，已有聊天与本次输入被清空，提示“登录状态已失效，已转为临时对话；本次不保存”。
3. 同一根因还导致：首条失败后点击重试被吞掉；聊天后点击历史/记忆/清除/草稿入口会清空匿名对话。

## A.2 根因链

1. `classifySession()`（约 1400–1406 行）在无 token 时，只要 `state.accountBound || hasLegacyContext()` 为真，就返回 `signed-out-with-context`。
2. `hasLegacyContext()`（约 1408–1414 行）把 `state.turns.length`、`state.panelKind`、`state.historyItems.length`、`state.memorySnapshot`、`state.draft`、`state.uid`、`state.token`、`state.mode === 'saved'` 全部计入。
3. 其中 `state.turns.length` 与 `state.panelKind` 是**页面级通用状态**：
   - 游客每轮成功回复都会让 `turns` 增加 2；
   - 游客打开受限面板会让 `panelKind` 变为 `history`/`memory`/`clear`/`draft`。
4. 因此：
   - 第 2 轮发送 → `classifySession() === 'signed-out-with-context'` → `sendMessage()` 的隔离分支（约 1570–1575 行）调用 `isolateSignedOutContext('removed')`，清空 `turns`、`chatEl`、`inputEl`，本次不发送；
   - 首条失败残留 1 个用户轮次 → 重试同样被隔离；
   - 打开历史 → `openHistoryPanel()`（约 759–777 行）先 `classifySession()`，得到待隔离 → `isolateSignedOutContext` 清空，再作为游客打开面板并提示登录。
5. `state.accountBound` 在初始化时由 `Boolean(state.uid && state.token)` 赋值（约 1722 行），在恢复保存成功（约 579 行）与 `resetAccountView`（约 531 行）中维护；它是“曾/仍绑定账号”的可信痕迹。
6. `switchAccount`（约 591–599 行）与 `storage` 监听（约 1703–1720 行）仍以 `state.accountBound || hasLegacyContext()` 或账号变化触发隔离，是真实退出/换号隔离的既有路径。
